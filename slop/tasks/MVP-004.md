# [MVP]-[004] Publish Safe Read-Only Summaries for Unsupported Topology

## Status: Implemented

## Scope

The strict `AtomicSnapshotSynchronizer` remains the sole full-snapshot path. It continues to reject an unsupported
physical slot topology before publishing any slots, assignments, or mutation-capable cache state.

The owner-authorized read-only MVP runtime now recognizes that typed rejection and runs a separately named fallback.
It repeats the required GET-only reads, verifies that printer and status identities are complete and that printer and
spool IDs are unique, then publishes a deliberately reduced snapshot containing only printers and spools. Virtual
trays and server assignments are fetched but discarded; they cannot become a `SlotKey` or an apparent assignment.

## Safety Properties

- The fallback is reachable only after the full synchronizer returns `UnsupportedTopology`.
- It publishes no slots and no assignments, so printer slot counts and assigned counts are zero and spool assignment
  fields are null.
- Every cache projection remains mutation-disabled. The degradation is surfaced through typed
  `CacheProjectionError.UnsupportedTopology` and `MutationDisabledReason.UnsupportedTopology`.
- Assignment POST and every NFC/tag write, overwrite, and clear path remain unbound from the MVP runtime.
- No live/private request, URL, API key, response, or inventory value was used in implementation or tests.

## Verification

- `MvpConnectionRuntimeTest.unsupportedTopologyPublishesOnlySafeReadOnlySummaries` proves that an unsupported tray
  produces summaries only, with no slots, assignments, or mutation availability.
