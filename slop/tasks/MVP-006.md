# [MVP]-[006] Resolve Evidence-Bound A1 Single External Slot Compatibility

## Status: Implemented

## Scope

The topology resolver now has one narrowly bounded compatibility rule for the owner-confirmed Bambu Lab A1 without
AMS. Bambuddy may report a virtual-tray identifier different from the documented assignment coordinate; that
identifier is never converted to a coordinate or interpreted by list order.

The rule resolves only when independent API data supplies all of the following:

- printer `model` is exactly `A1`;
- status contains exactly one `vt_tray`;
- the current printer assignments contain exactly one entry at `ams_id=255`, `tray_id=0`.

The resolved external slot always uses the isolated shared `255/0` rule coordinates. Any absent, unknown, positive,
duplicate, contradictory, AMS, or multi-slot evidence remains unsupported. Assignment POST, NFC write, overwrite,
and clear paths remain unbound.

## Safety Properties

- A mutable display name is not topology evidence.
- The API model is required topology evidence. `ams_exists` is retained as nullable status capability metadata but
  is not attached-AMS evidence: it cannot override the independently proven single physical slot.
- Existing assignment evidence identifies only the documented coordinates; the virtual-tray identifier is retained
  only for its label and is never used as an `ams_id` or `tray_id`.
- No private URL, token, response, inventory data, mutation, NFC write, or live request was used.
