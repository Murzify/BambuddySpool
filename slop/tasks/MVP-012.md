# MVP-012 — Retain Foreground NFC Ownership Through Physical Mutation

## Scope

Fix the Android-only foreground-reader lifecycle discovered on the supported Honor device: the reader must retain
ownership of the held tag while the existing NDEF writer and independent read-back execute.

## Delivered

- The Android bridge now retains foreground reader mode from the accepted tag through the existing NDEF writer and
  its independent read-back.
- A framework-free lifecycle state machine accepts reader callbacks only while awaiting a tag. It rejects callbacks,
  cancellation, and a second read request during physical mutation, so no callback can replace the authorized tag.
- The bridge clears its process-local framework tag and disables reader mode exactly once in `finally`, after both
  successful and failed writer returns.
- Pre-mutation cancellation still clears the tag and disables reader mode. NFC intent routing outside this workflow
  remains owned by the Activity as before.

## Verification


The focused Android unit tests prove enable-to-mutation continuity, ignored callbacks/cancellation during mutation,
and one terminal disable on both normal and failure-equivalent paths. The Android debug APK assembled successfully.

## Safety Notes

No private Bambuddy request, POST, physical NFC write, tag lock, secret logging, or private fixture capture was
performed.
