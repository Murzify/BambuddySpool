# [MVP]-[005] Normalize Finite Over-Consumption in Read-Only Spool Snapshots

## Status: Implemented

## Scope

An owner-authorized read-only diagnosis established that some otherwise valid inventory records can have finite,
nonnegative `weight_used` greater than `label_weight`. `SpoolDto` now represents that over-consumption as an empty
spool with `remainingGrams = 0`. This preserves the valid read-only snapshot rather than rejecting its whole
response.

## Safety Properties

- Negative `label_weight`, `core_weight`, and `weight_used` remain invalid contract values.
- Non-finite `weight_used` remains an incompatible response; strict JSON parsing and DTO validation both fail
  closed.
- The normalization is limited to the derived read-only remaining quantity. It changes no API request, mutation,
  URL, token, TLS, or diagnostic behavior.
- No private URL, API key, response, or inventory value is present in this report or committed tests.

## Verification

- `BambuddyDtoMappingTest.finiteOverConsumptionIsClampedToEmptyInsteadOfRejectingTheSpool` verifies deterministic
  DTO normalization.
- `BambuddyDtoMappingTest.negativeOrNonFiniteSourceWeightsRemainIncompatible` verifies invalid source values stay
  typed failures.
- `AtomicSnapshotSynchronizerTest.fullSnapshotPublishesAnEmptySpool` verifies a fully valid snapshot with zero
  remaining grams publishes atomically.
