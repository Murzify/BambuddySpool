# MVP-001 Completion Report

## Summary

Wired the shared connection form into the production root. First launch now presents Setup, and the Settings root
uses the same form with observable non-secret settings presentation. The graph now uses an explicit connection-aware
empty-cache boundary instead of an unqualified perpetual loading placeholder.

## Security Boundary

This task deliberately does not make Bambuddy usable yet. Before `[SEC]-[001]` and `[SEC]-[002]`, the runtime has
no token persistence and no network transport. Test and Save therefore fail closed with a clear user-facing message;
they do not send a request, retain the entered token, create a connection, schedule sync, or enable mutations.

The following remain disabled and unchanged: assignment POST, NFC tag write, overwrite, and clear. No `.env.local`
file was read and no private Bambuddy instance request was made.

## Changed Areas

- `app/App.kt` renders Setup for the unconfigured first run and the shared Settings connection form otherwise.
- `app/bootstrap` creates and lifecycle-closes the MVP connection runtime.
- `app/root` exposes only the shared form and observable non-secret settings; token text, authorization, and
  transient workflows remain outside restored state.
- `app/connection/MvpConnectionRuntime.kt` supplies the fail-closed validator, non-secret settings flow, and
  connection-aware empty-cache projection state.

## Verification

```text
./gradlew :shared:testAndroidHostTest --tests '*MvpConnectionRuntimeTest' \
  --tests '*ConnectionForm*' --tests '*RootComponentTest'
./gradlew spotlessApply
./gradlew :androidApp:assembleDebug
git diff --check
```

Android CLI smoke on the local emulator installed the debug APK and confirmed:

- first launch renders `Connect Bambuddy` with URL/token/Test/Save;
- Settings renders the shared `Connection` form;
- a syntactically valid local test input shows the SEC-001/SEC-002 safety-gate message without sending a request.

The app was force-stopped after the smoke so the unsaved token text was discarded.

## Follow-up Gates

- `[SEC]-[001]` must provide Keystore-backed token storage and backup/invalidation coverage.
- `[SEC]-[002]` must enforce redirects, HTTP consent, and TLS policy below the UI.
- After both gates, a separately owner-authorized read-only instance smoke may validate, save, sync, and browse
  cached Spools/Printers. The deferred `[TEST]-*` matrix remains release hardening.
